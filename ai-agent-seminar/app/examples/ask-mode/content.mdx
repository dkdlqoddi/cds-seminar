## 1. 시나리오

3년 전 퇴사한 선임이 남긴 `vibration_analysis.py`. 매주 한 번씩 돌리고 결과만 보고하던 스크립트인데, 어느 날 갑자기 결과가 이상해졌습니다.

본인이 짠 코드가 아니어서 손대기 무서운 상황. **Ask 모드**가 정확히 이 자리에 쓰입니다.

<Callout kind="info" title="Ask 모드의 핵심">
Ask 모드는 **읽기만 합니다**. 파일을 수정하지도, 명령을 실행하지도 않습니다.
"이 코드가 무슨 일을 하는지" 알고 싶을 때 안전하게 쓸 수 있는 모드입니다.
</Callout>

대상 스크립트는 다음과 같습니다.

<CodeBlock
  filename="vibration_analysis.py (선임 작품)"
  lang="python"
  code={`import numpy as np
import pandas as pd
from scipy.signal import butter, filtfilt
from scipy.fft import rfft, rfftfreq

FS = 1000.0
CUTOFF = 50.0
ORDER = 4
THRESHOLD_G = 2.5


def _bp(x):
    b, a = butter(ORDER, CUTOFF / (FS / 2), btype="low")
    return filtfilt(b, a, x)


def analyze(path):
    df = pd.read_csv(path)
    sig = _bp(df["accel_z"].values)
    N = len(sig)
    spec = np.abs(rfft(sig)) / N
    freqs = rfftfreq(N, 1 / FS)
    peak_idx = np.argmax(spec[1:]) + 1
    peak_hz = freqs[peak_idx]
    peak_g = sig.max() / 9.81
    flag = peak_g > THRESHOLD_G
    return {"peak_hz": peak_hz, "peak_g": peak_g, "flag": flag}


if __name__ == "__main__":
    import sys, json
    print(json.dumps(analyze(sys.argv[1])))`}
/>

<Callout kind="tip" title='왜 "다른 코드는 절대 손대지 마"라고 적었나'>
Code 모드에 일을 시키면 모델이 "이왕 보는 김에 깔끔하게 정리해드릴까요"라며
주변 코드까지 손대는 경우가 종종 있습니다. **변경 범위를 명시적으로 박아두면**
diff가 작아져서 검토가 쉬워지고, 사이드이펙트도 줄어듭니다.
</Callout>

## 5. 검증 방법

<Callout kind="check" title="수정 후 직접 확인할 것">
1. `git diff` 또는 VS Code의 변경 표시로 **딱 한 줄만 바뀌었는지** 본다.
2. 새 장비에서 받은 CSV 한 개로 `python vibration_analysis.py new_data.csv` 실행 → JSON이 정상 출력되는지.
3. `peak_hz` 값이 새 장비의 알려진 공진 주파수와 비슷한 범위인지 (예: 약 60Hz 부근 회전체라면 그 부근에 피크).
4. 옛날 장비 CSV로도 똑같은 흐름을 한 번 돌려본다 — 다만 옛 데이터는 FS=1000이므로 결과가 다를 수 있음 → 결국 **장비별로 FS를 인자로 받게** 리팩토링하는 게 정답이지만, 그건 다음 작업으로.
</Callout>
