## 한 표로 비교

| 항목 | 일반 챗봇 (ChatGPT 웹) | AI 에이전트 (Roo Code) |
| --- | --- | --- |
| 입력 | 텍스트 (드래그&드롭 파일) | 텍스트 + **내 컴퓨터 폴더 전체** |
| 출력 | 텍스트, 가끔 코드 | 텍스트 + **실제 파일 생성/수정** |
| 실행 | 못 함. 사람이 복사해서 돌려야 함 | **직접 명령을 실행하고 결과를 본다** |
| 단계 | 한 턴에 한 답 | **여러 도구를 연달아 호출** |
| 검증 | 사람이 결과를 다시 입력해야 함 | 결과를 자기가 보고 다음 행동 결정 |
| 데이터 위치 | 외부 서버 | (Ollama 사용 시) **사내/로컬에 머무름** |

## 같은 일을 시키면 어떻게 달라지는가

업무: **"measurements/ 폴더 안 50개 CSV에서 force 컬럼 평균을 한 표로 만들어줘"**

### 챗봇 방식 (ChatGPT 웹)

1. 파일 1~2개를 드래그&드롭으로 올린다 (50개는 너무 많아서)
2. "이런 형식인데 평균 내는 코드 짜줘"라고 물어본다
3. 받은 코드를 복사해서 본인 PC에서 직접 실행한다
4. 에러가 나면 다시 챗봇에 가서 "이런 에러 났는데"라고 묻는다
5. 결과가 이상하면 다시 가서 또 묻는다 → **사람이 매 단계의 다리 역할**

## 그렇다고 챗봇이 나쁜 건 아닙니다

<Callout kind="info" title="언제 챗봇이 더 낫나">
- **개념 질문**: "FFT가 뭐야?", "이 논문의 요지가 뭐야?"
- **글쓰기 도움**: 메일 초안, 문서 다듬기
- **빠른 1회성 답**: 단위 변환, 정규식 한 줄

내 컴퓨터의 파일을 건드릴 필요가 없는 일이라면 챗봇이 더 가볍습니다.
</Callout>

<Callout kind="check" title="에이전트가 진짜 가치있는 순간">
- 같은 작업을 **여러 파일에 반복**해야 할 때
- **여러 단계**를 거쳐야 결과가 나올 때 (불러오기 → 가공 → 저장 → 검증)
- 결과를 **실행해서 검증**까지 해야 끝나는 작업
- 회사 데이터를 **외부에 보내면 안 되는** 작업 (사내 Ollama 전제)
</Callout>

## 사내 Ollama를 쓰는 이유

이 세미나는 OpenAI/Claude API 대신 **사내 Ollama 엔드포인트**를 사용하는 것을 전제로 합니다.

| 외부 API (OpenAI, Anthropic 등) | 사내 Ollama |
| --- | --- |
| 결과 품질이 매우 높다 | 모델 크기에 따라 다르지만 충분히 쓸 만 |
| 데이터가 외부 서버로 나간다 | **데이터가 사내망 밖으로 나가지 않음** |
| API 사용료 발생 | 사내 GPU 자원 내 무료 |
| 보안팀 승인 필요 | (이미 사내 인프라이므로) 정책 부담 적음 |

**측정 데이터, 도면 메타데이터, 사내 코드** 같은 자산을 다룬다면 외부 API에 그대로 보내는 것은 위험할 수 있습니다. Ollama는 이 문제를 회피합니다.
