## 두 갈래 길: 네이티브 Windows vs WSL2

n8n은 Node.js 기반이라 두 환경 모두에서 동일하게 동작합니다. 다만 일상적으로
쓸 때의 체감 차이가 큽니다.

| 항목 | 네이티브 Windows | WSL2 (Ubuntu) |
| --- | --- | --- |
| 설치 난이도 | 낮음 — Node.js exe 한 번 | 중간 — WSL 설치 + 배포판 + Node |
| Node.js/npm 속도 | 보통 (백신·Defender 검사 영향) | 빠름 — Linux 파일시스템 |
| 파일 경로 | `%USERPROFILE%\.n8n\` | `~/.n8n` (Linux 홈) |
| 로컬 파일 노드 | `C:\` 경로 그대로 | `/mnt/c/` 를 거쳐 접근 |
| 브라우저로 `localhost:5678` | 됨 | 됨 (WSL2가 자동 포워딩) |
| Windows 작업 스케줄러 | 직접 등록 가능 | WSL 측 systemd / `wsl --exec` 필요 |
| 사내 정책 | 대부분 즉시 허용 | Hyper-V/가상화 활성 필요 (보안팀 사전 문의) |

<Callout kind="tip" title="언제 어느 쪽을 고를까">
- **측정 폴더가 `C:\` 또는 사내 공유 폴더에 있다** → 네이티브 Windows가 단순합니다.
- **Python/uv·Docker·Linux 툴체인을 같이 쓴다, 또는 매크로 무거운 Node 빌드가 답답하다** → WSL2가 쾌적합니다.
- **둘 다 깔아도 무방**합니다. 데이터 폴더가 분리되니 워크플로우는 JSON export로 옮깁니다.
</Callout>

## 1분 시작: `npx n8n`

가장 빠른 방법입니다. 영구 설치 없이 즉석에서 돌립니다.

```powershell
# PowerShell 또는 Windows Terminal에서
npx n8n
```

처음 실행 시 npm이 패키지를 받아오느라 30초~1분 정도 걸립니다.
끝나면 자동으로 브라우저가 열리며 `http://localhost:5678` 로 들어갑니다.

<Callout kind="check" title="첫 실행에서 묻는 것">
- **이메일 주소** — 로컬 계정 식별용 (외부로 나가지 않음)
- **비밀번호** — 동료가 이 PC를 만지지 못하도록 설정해 두는 게 좋습니다
- 데이터는 모두 `%USERPROFILE%\.n8n\` 안에 SQLite로 저장됩니다
</Callout>

## 영구 설치: PC를 켜자마자 자동 실행

세미나 종료 후에도 매일 쓸 거라면 한 번만 글로벌 설치합니다.

```powershell
npm install -g n8n

# 데이터 폴더 미리 확인
echo $env:USERPROFILE\.n8n
```

PC 부팅과 함께 백그라운드에서 돌리려면 Windows 작업 스케줄러나
[`pm2-windows-service`](https://www.npmjs.com/package/pm2-windows-service)를 씁니다.
세미나에서는 `npx n8n` 만 충분히 다룹니다.

### 1. WSL2 + Ubuntu 설치

관리자 권한 **PowerShell** 에서:

```powershell
# 기본 Ubuntu 배포판이 함께 설치됩니다 (재부팅 필요할 수 있음)
wsl --install

# 이미 wsl이 깔려 있다면 버전만 확인
wsl --status
wsl --set-default-version 2
```

재부팅 후 시작 메뉴에서 **Ubuntu** 를 한 번 실행하면 사용자명·비밀번호를 묻습니다.
여기서 만든 계정이 WSL2 안의 리눅스 사용자입니다.

### 2. WSL2 안에서 Node.js 20 LTS 설치

Ubuntu가 기본으로 주는 Node.js는 구버전이라 **nvm**으로 20 LTS를 깝니다.

```bash
# WSL2(Ubuntu) 터미널에서
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
exec $SHELL

nvm install 20
nvm alias default 20
node -v   # v20.x 확인
```

<Callout kind="check" title="사내망에서 npm registry를 사내 미러로">
사내망에서는 공용 npm registry가 막혀 있을 수 있습니다. WSL2 쉘 안에서 한 번만:

```bash
npm config set registry https://repo.samsungds.net/artifactory/api/npm/npm-remote/
npm config get registry
vim ~/.npmrc
# ~/.npmrc에 아래 내용 입력
# registry=http://repo.samsungds.net/artifactory/api/npm/npm-remote/
# strict-ssl=false
# @artifact:registry=https://artifact.samsungds.net/artifactory/api/npm/npm-artifact-virtual/
# https-proxy=http://nexus.adpaas.cloud.samsungds.net/
# proxy=http://nexus.adpaas.cloud.samsungds.net/

```

프록시가 필요한 환경이라면 `~/.npmrc` 에 `proxy`, `https-proxy` 를 추가합니다.
</Callout>

### 3. n8n 실행

```bash
# 1분 시작: 영구 설치 없이
npx n8n

# 또는 영구 설치
npm install -g n8n
GENERIC_TIMEZONE=Asia/Seoul N8N_DIAGNOSTICS_ENABLED=false n8n
```

브라우저는 **Windows 쪽** Edge/Chrome에서 그대로 `http://localhost:5678` 로 들어갑니다.
WSL2가 자동으로 포트를 호스트와 연결합니다.

### 5. 자동 실행 (선택)

PC를 켜자마자 n8n을 띄우고 싶다면:

```powershell
# Windows 작업 스케줄러에 등록 — 작업 동작에 다음 입력
wsl -d Ubuntu -- bash -lc "GENERIC_TIMEZONE=Asia/Seoul n8n"
```

또는 WSL2 안에서 systemd를 켠 뒤 (`/etc/wsl.conf` 의 `[boot] systemd=true`) `pm2` 로 등록합니다.
세미나 범위는 아닙니다 — 평소엔 Ubuntu 터미널에서 `n8n` 한 줄로 충분합니다.

## 사내 LLM 게이트웨이를 어떻게 부르는가

사내 GPT-OSS 게이트웨이는 **OpenAI 호환 엔드포인트**입니다. 즉, n8n의 OpenAI 노드를
쓰는 게 가장 매끈하지만 — 이 노드는 헤더 커스텀이 제한적이라 `x-dep-ticket` 같은
사내 인증 헤더를 깔끔히 넣기 어렵습니다.

따라서 이 세미나에서는 **항상 HTTP Request 노드** 를 씁니다. 더 단순하고, 무엇이
어디로 나가는지 그대로 보입니다.

### Manual Trigger 클릭 → 응답 확인

`Execute Workflow` 버튼을 누르면 게이트웨이가 응답합니다. HTTP Request 노드를 클릭하면
오른쪽 패널에 들어온 JSON이 그대로 보이고, 그중 `choices[0].message.content` 가 모델이 만든 답입니다.

```json
{
  "id": "chatcmpl-abc...",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "1) 평균과 표준편차 — 분포의 중심과 산포도\n2) 최소/최대 — 이상치 후보\n3) 사분위수(Q1, Q3) — 박스플롯 형태로 한눈에 ..."
      },
      "finish_reason": "stop"
    }
  ]
}
```

이 한 워크플로우가 동작했다면 **이 세미나의 절반은 끝난 셈** 입니다. 4강의 5가지 예제는
이 골격에 트리거와 후처리 노드를 더한 것에 불과합니다.

## 자주 만나는 트러블슈팅

| 증상 | 원인 / 해결 |
| --- | --- |
| `npx n8n` 첫 실행이 멈춤 | 사내망에서 npm registry 접근이 막힘. `npm config set registry <사내 미러>` |
| 401 / 403 | `x-dep-ticket` 만료 또는 헤더 이름 오타. 사내 AI 플랫폼에서 재발급 |
| `ECONNREFUSED` | 게이트웨이 URL의 호스트명/포트 오타. 브라우저로 그대로 GET 해서 reachable 여부 확인 |
| 응답이 오긴 하는데 한국어가 깨짐 | 거의 없으나, `Content-Type: application/json; charset=utf-8` 명시 |
| 워크플로우는 도는데 결과가 갱신 안 됨 | 좌상단 **Save** 안 눌렀거나, 데이터 핀(pin)이 옛날 값에 박혀 있음 |
| `wsl --install` 이 `0x80370102` 로 실패 | BIOS 가상화(VT-x/SVM) 꺼져 있음. 부팅 시 BIOS에서 활성화 |
| WSL2에서 `localhost:5678` 이 Windows 브라우저에서 안 열림 | `wsl --shutdown` 후 재실행. 또는 보안 SW가 9P 프로토콜을 차단하는지 확인 |
| WSL2에서 CSV 처리가 너무 느림 | 측정 폴더를 `/mnt/c/...` 가 아닌 WSL2 홈(`~/`)으로 옮기면 수 배 빨라짐 |
| WSL2에서 사내망 DNS 해석 실패 | `/etc/resolv.conf` 가 덮어쓰여 그럴 수 있음. `/etc/wsl.conf` 에 `[network] generateResolvConf = false` 추가 후 `wsl --shutdown` |
