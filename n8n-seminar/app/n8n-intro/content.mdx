## 정의: 한 문장으로

**n8n**(eɪt-en-eɪt-en)은 **노드(블록)** 를 **선(connection)** 으로 이어
일련의 작업을 자동으로 수행하게 만드는 **워크플로우 자동화 도구**입니다.
오픈소스이며, 사내 PC·서버에 직접 설치해서 쓸 수 있습니다.

세 가지 키워드만 기억하면 됩니다.

- **노드**: 한 가지 일을 하는 블록 (파일 읽기, HTTP 호출, IF 분기 등)
- **선**: 노드 사이의 데이터 흐름 — 앞 노드의 출력이 뒷 노드의 입력
- **트리거**: 워크플로우를 시작시키는 첫 노드 (시간, 파일 변경, Webhook 등)

## 익숙한 비유: LabVIEW · Excel 매크로 · Jenkins 사이 어딘가

<Callout kind="tip" title="비유로 이해하기">
**LabVIEW 블록 다이어그램**처럼 박스를 선으로 연결해 만들지만, 실시간 신호 처리가 아니라
**파일·이메일·HTTP·DB 같은 "사무 자동화 영역"** 을 다룹니다.

**Excel 매크로**처럼 반복 작업을 자동화하지만, 매크로는 한 PC에 갇힌 반면 n8n 워크플로우는
**서버에서 24시간 동작**하고 누구나 그림으로 흐름을 볼 수 있습니다.

**Jenkins 파이프라인**처럼 단계별 실행 로그가 남고 재시도가 가능하지만, Jenkins는 빌드/배포에,
n8n은 **데이터·알림·LLM 호출** 에 더 어울립니다.
</Callout>

## 워크플로우의 4가지 구성요소

| 구성요소 | 하는 일 | 일상 비유 |
| --- | --- | --- |
| **Trigger** | 워크플로우를 시작 | 알람시계 / 우체통 |
| **Node** | 한 단계의 작업 수행 | 컨베이어벨트의 한 작업자 |
| **Connection** | 데이터 흐름 (앞 출력 → 뒤 입력) | 컨베이어벨트 자체 |
| **Execution** | 한 번의 실행 기록 + 로그 | 작업일지 |

## n8n이 잘하는 일과 못하는 일

| 잘함 | 못함 |
| --- | --- |
| 파일·이메일·HTTP·DB·메신저 알림을 엮는 **오케스트레이션** | 실시간 신호 처리, ms 단위 응답 |
| 단계별 로그·재시도·에러 알림 | 무거운 행렬 연산·이미지 처리 (가능은 하지만 느림) |
| 사내 LLM 게이트웨이를 HTTP 노드로 그대로 호출 | GPU 추론 자체 |
| 비개발자도 그림으로 흐름 이해 | 100 ms 내 응답을 요구하는 장비 제어 |

<Callout kind="check" title="언제 쓰면 좋은가">
"Python으로 짜면 50줄짜리 스크립트인데, 매일 새벽에 돌리고 싶고, 다른 팀원도 흐름을 봐야 하고,
실패하면 누군가 알아야 한다"  —  이런 상황이면 n8n이 거의 항상 정답입니다.
</Callout>

## 자체 호스팅 vs n8n.cloud

| 항목 | 자체 호스팅 (사내 PC/서버) | n8n.cloud |
| --- | --- | --- |
| 비용 | 무료 (Apache 2.0 기반의 Fair-code) | 유료 구독 |
| 사내망 자원 접근 | 가능 (사내 LLM 게이트웨이, 파일서버 등) | 어려움 (외부망에서만 동작) |
| 설치 부담 | Node.js만 설치되어 있으면 1분 | 회원가입만 |
| 보안 검토 | 사내 보안팀 검토 필요 없음 (PC 안에서 동작) | 외부 SaaS 검토 필요 |

**이 세미나는 자체 호스팅만 다룹니다.** 사내 데이터를 외부 클라우드에 올릴 수 없는 환경을 전제로 합니다.
