<Callout kind="tip" title="언제 어느 쪽을 만드나">
- **여러 단계가 섞인 작업의 진입점**(설계 후 코드 → 테스트) — primary로.
- **특정 폴더만 / 특정 동작만** 하는 도구 — subagent로.<br/>
  실수했을 때 피해 범위가 좁아진다는 게 가장 큰 가치입니다.
</Callout>

## 어디에 저장하나

| 종류 | 위치 (cmd) | 위치 (PowerShell) |
| --- | --- | --- |
| 프로젝트 전용 | `.opencode\agents\이름.md` | `.\\.opencode\\agents\\이름.md` |
| 글로벌 (개인) | `%USERPROFILE%\.config\opencode\agents\이름.md` | `$env:USERPROFILE\.config\opencode\agents\이름.md` |

파일명이 곧 에이전트 이름입니다 — `csv-cleaner.md` 를 만들면 `@csv-cleaner` 로 부릅니다.

## frontmatter 필드

<CodeBlock
  filename=".opencode\agents\csv-cleaner.md (구조 설명용)"
  lang="md"
  code={`---
description: data/ 폴더의 측정 CSV를 정리한다 (raw 보존, clean 에 저장).
mode: subagent                       # primary | subagent | all
model: samsungds/gpt-oss-120b        # (선택) 모델 오버라이드
temperature: 0.1                     # (선택) 낮을수록 단호함
permission:
  edit: ask                          # 기존 파일 수정
  write: allow                       # 새 파일 생성 (data/clean 에만 한정 시키려면 본문에 명시)
  bash: deny                         # 쉘 명령 금지
  webfetch: deny
---

(여기에 시스템 프롬프트 — 다음 단락 참고)
`}
/>

핵심 필드:

- **`description`** *(필수)* — primary가 "언제 이 subagent를 부를지" 판단하는 한 줄. **동작과 입력**을 구체적으로.
- **`mode`** — `subagent` 가 가장 흔함. `primary`로 두면 <KeystrokeBadge>Tab</KeystrokeBadge> 모드 순환에 들어감.
- **`model`** — 사내 빌드의 기본 모델로 충분하면 생략.
- **`temperature`** — 정리·정량 작업은 `0.1` 정도로 낮춤. 자유 설명은 `0.4`.
- **`permission`** — 4가지 도구에 대해 `allow / ask / deny`.

## 예제 ① · `csv-cleaner` 서브에이전트

목표: `data/raw/` 의 측정 CSV를 정리해 `data/clean/` 에 저장. **raw는 절대 안 만진다.**

<CodeBlock
  filename=".opencode\agents\csv-cleaner.md"
  lang="md"
  code={`---
description: data/raw/ 의 CSV를 헤더 정리·결측 보간 후 data/clean/ 에 저장한다. raw 는 절대 수정하지 않는다.
mode: subagent
temperature: 0.1
permission:
  edit: ask
  write: allow
  bash: ask
  webfetch: deny
---

너는 측정 CSV 정리 전용 어시스턴트다.

규칙:
1. 입력은 항상 data/raw/*.csv 다. 다른 폴더의 파일을 만지지 않는다.
2. 출력은 항상 data/clean/<같은이름>.csv 다. raw 파일은 어떤 경우에도 수정·삭제하지 않는다.
3. 정리 절차: (a) 헤더 표준화 (b) 결측치 선형 보간 (c) 타임스탬프 ISO8601 통일.
4. 처리 후 채팅창에 "입력 행/열 → 출력 행/열, 결측 보간 N건"을 한 줄로 보고한다.
`}
/>

## 예제 ② · `waveform-explainer` 서브에이전트

목표: **수정은 하지 않고 설명만**. 선임이 남긴 분석 스크립트를 줄 단위로 풀어 설명한다.

<CodeBlock
  filename=".opencode\agents\waveform-explainer.md"
  lang="md"
  code={`---
description: 진동 분석 Python 스크립트를 줄 단위로 설명한다. 코드를 수정하거나 명령을 실행하지 않는다.
mode: subagent
temperature: 0.4
permission:
  edit: deny
  write: deny
  bash: deny
  webfetch: deny
---

너는 진동 분석 스크립트 해독 전용 어시스턴트다.

규칙:
1. 사용자가 가리킨 파일만 읽는다. 다른 파일을 임의로 열지 않는다.
2. 코드를 수정·실행·생성하지 않는다. 무엇을 해도 결국 "왜 이렇게 짰는지"를 한국어로 설명만 한다.
3. 핵심 함수 위주로 3~5줄 단위로 묶어 설명하고, FFT / 윈도윙 / 샘플레이트 같은 도메인 용어는 한국어 풀이를 옆에 단다.
4. 마지막에 "변수 한 곳만 안전하게 바꾸려면" 어디를 만져야 할지 한 줄 가이드를 덧붙인다.
`}
/>

## 흔한 실수 3가지

<Callout kind="warn" title="에이전트 만들 때 자주 깨지는 곳">
1. **<code>mode: subagent</code> 로 만들고 <KeystrokeBadge>Tab</KeystrokeBadge> 으로 안 보인다고 당황한다** — subagent는 Tab 순환에 들어가지 않습니다. <KeystrokeBadge>@</KeystrokeBadge>이름 으로만 부르거나, primary가 description을 보고 자동 위임하게 둡니다.
2. **<code>description</code> 이 너무 추상적** — "도와주는 어시스턴트" 같은 문구는 primary가 언제 부를지 못 정합니다. <strong>입력 / 출력 / 어디서</strong>를 구체적으로 적으세요.
3. **<code>permission</code> 을 다 <code>allow</code> 로 풀어둠** — 좁은 권한이 subagent의 핵심 가치입니다. 안 쓰는 도구는 <code>deny</code>, 가끔 쓰는 도구는 <code>ask</code>로 시작하세요.
</Callout>
