## 무엇을 배우는가

직접 try/except 와 캐시 dict 를 짜 본 사람은 알겠지만, "오늘만 재시도 좀 추가하자"는 마음으로 짠 코드는
대개 다음 달까지 살아 남습니다. Prefect 의 `@task` 인자 세 개를 쓰면 이 모든 게 한 줄 설정으로 끝납니다.

| 인자 | 무엇을 해주나 | 어울리는 상황 |
| --- | --- | --- |
| `retries=N` | 실패하면 자동으로 N 번 더 호출 | DB/HTTP 일시 단절, 파일 잠금 |
| `cache_policy=INPUTS` | 같은 입력으로 다시 부르면 결과를 재계산하지 않음 | 비싼 통계, 외부 API 응답 |
| `timeout_seconds=T` | T 초 안에 끝나지 않으면 task 실패로 종료 | 멈춘 외부 호출, 무한 루프 보호 |

## 코드

<CodeBlock
  filename="flows/02_retry_cache.py"
  lang="python"
  code={`import random, time
from datetime import timedelta
from prefect import flow, task, get_run_logger
from prefect.cache_policies import INPUTS


@task(retries=3, retry_delay_seconds=1)
def flaky_fetch(url: str) -> str:
    logger = get_run_logger()
    if random.random() < 0.6:
        logger.warning("temporary failure on %s — Prefect will retry", url)
        raise ConnectionError("simulated transient failure")
    logger.info("fetch ok: %s", url)
    return f"<html>{url}</html>"


@task(cache_policy=INPUTS, cache_expiration=timedelta(minutes=10))
def expensive_compute(lot_id: str) -> dict:
    logger = get_run_logger()
    logger.info("running expensive_compute for %s …", lot_id)
    time.sleep(1.0)
    return {"lot_id": lot_id, "score": 0.873}


@task(timeout_seconds=2)
def maybe_hangs(seconds: float) -> str:
    time.sleep(seconds)
    return f"slept {seconds}s"


@flow(name="retry-cache-demo", log_prints=True)
def demo() -> None:
    html = flaky_fetch("http://internal.example/data")
    print(f"got html length={len(html)}")

    a = expensive_compute("A001")
    b = expensive_compute("A001")  # 빠름 (cached)
    print(f"a == b ? {a == b}, both = {a}")

    print(maybe_hangs(1.0))
    try:
        maybe_hangs(5.0)
    except Exception as e:
        print(f"timeout caught as expected: {type(e).__name__}")`}
/>

## 무엇을 보게 되는가

- `flaky_fetch` 는 60% 확률로 `ConnectionError` 를 던지지만, `retries=3` 덕에 사실상 거의 모든 시도가 성공합니다. 로그에는 재시도가 일어났던 사실이 **그대로** 남습니다 — 어떤 에러를 몇 번 만에 통과했는지 추적 가능합니다.
- `expensive_compute("A001")` 을 두 번 부르면 두 번째는 거의 0초에 끝나고, UI 에서는 두 번째 task run 이 **Cached** 상태로 표시됩니다.
- `maybe_hangs(5.0)` 은 `timeout_seconds=2` 때문에 2초 만에 잘려 `TimeoutError` 가 발생합니다.

<Callout kind="warn" title="현실 운영 주의">
- `retries` 는 만능이 아닙니다. **멱등하지 않은** 작업(예: 같은 행을 두 번 INSERT) 에 무지성으로 retry 를 붙이면
  중복 적재가 일어납니다. 메인 예제(예제 3) 에서는 unique index 또는 UPSERT 로 막는 패턴을 같이 봅니다.
- `cache_policy=INPUTS` 는 **함수 인자만** 캐시 키로 씁니다. 함수가 외부 파일/DB 의 상태에 의존한다면
  custom `cache_key_fn` 이 필요합니다. 잘못 잡으면 "어제와 똑같은 입력인데 결과가 옛날 것" 같은 미묘한 버그가 납니다.
</Callout>
